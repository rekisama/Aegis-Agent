# 服务器启动指南

## 不同的启动模式

### 1. 生产模式（推荐用于日常使用）
```bash
cd web
python start_server.py
```
- **特点**：禁用自动重载，最稳定
- **适用场景**：日常使用，不需要频繁修改代码
- **优势**：不会因为文件变化而重启

### 2. 智能监控模式（推荐用于开发）
```bash
cd web
python start_server_smart.py
```
- **特点**：只监控核心代码目录，排除虚拟环境和动态工具目录
- **适用场景**：开发时修改核心代码，同时避免动态工具创建触发重载
- **优势**：开发体验好，不会因为工具创建而重启

### 3. 动态工具开发模式（专门用于工具开发）
```bash
cd web
python start_server_dynamic.py
```
- **特点**：专门为动态工具开发优化，完全排除动态工具目录
- **适用场景**：频繁创建和测试动态工具
- **优势**：工具创建不会触发服务器重启

### 4. 开发模式（传统开发模式）
```bash
cd web
python start_server_dev.py
```
- **特点**：监控所有Python文件，包括虚拟环境
- **适用场景**：传统开发模式，需要监控所有文件变化
- **注意**：可能会因为pip安装等操作触发重载

## 问题解决

### 服务器重启问题
如果遇到服务器频繁重启，请使用以下模式：

1. **日常使用**：使用 `start_server.py`（生产模式）
2. **开发时**：使用 `start_server_smart.py`（智能监控模式）
3. **工具开发**：使用 `start_server_dynamic.py`（动态工具开发模式）

### WebSocket连接断开
如果遇到WebSocket连接断开错误，这通常是因为：
1. 服务器重启时连接被强制关闭
2. 使用带重载的启动模式时，动态工具创建触发了重载

**解决方案**：
- 使用不带重载的启动模式
- 或者使用智能监控模式，排除动态工具目录

## 最佳实践

1. **日常使用**：使用生产模式 `start_server.py`
2. **开发核心功能**：使用智能监控模式 `start_server_smart.py`
3. **创建动态工具**：使用动态工具开发模式 `start_server_dynamic.py`
4. **调试问题**：使用开发模式 `start_server_dev.py`
